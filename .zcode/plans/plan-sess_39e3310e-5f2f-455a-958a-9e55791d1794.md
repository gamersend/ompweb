### Phase 0 — Unblock `*.r.red.mba` (one command, fixes a week-old outage)

razer's fabric is **already fully provisioned** — registry entry, CoreDNS wildcard, Porkbun mirror, Caddy with the Porkbun module, a valid `*.r.red.mba` cert, Gatus monitors. It's all shadowed because **`tailscale serve` on razer has claimed TCP :443** (pointing at agenthub `:3170`), so tailscaled answers every `*.r.red.mba` handshake with `no webserver configured for name/port`. That's why `livekit.r.red.mba` has been 0/50 red in Gatus while the neon analog is 100% green.

- `sudo tailscale serve --https=443 off` on razer (leaves the `:8443 → 7880` mapping intact).
- Re-home agenthub if you still need it remotely: `tailscale serve --bg --https=9443 http://127.0.0.1:3170` (water/unraid pattern — they never claim :443).
- Verify: `https://livekit.r.red.mba/` → 200 and its Gatus monitor goes green.
- **Hardening (recommended):** two detectors exist and are structurally blind to this — the serve-guard is water-only (no ssh), and the watchdog's check substring-matches `":443"` against text output instead of parsing `--json`. I'll generalize the guard to every registry host and fix the watchdog's check so this can't hide again.

### Phase 1 — razer becomes the voice host

- Install `uv`; recreate pipecat's venv **pinned to the same interpreter** as neon's (pipecat/aiortc wheels lag 3.14 — razer's system python is linuxbrew 3.14, so this matters).
- Carry the state pipecat actually needs, which is more than the repo:
  - `~/fire-data/hotline-media` (99 MB, 1552 files — roster card art; pipecat 404s without it)
  - `CHARACTERS_DIR` tree (currently a **different repo** on neon: `nexus/nexus-middleware/characters`)
  - `HOTLINE_ROSTER_MANIFEST` (`simli/public/hotline-roster.json` — lives in the *web* repo, which is moving elsewhere)
- Postgres: new container on razer, loopback-only on a free port, restored from a `pg_dump` of neon's (1 row / 7.6 MB). Written as a compose file this time — today it's a bare `docker run` with no declarative source.
- systemd units on razer: `hotline-pipecat` (plain HTTP on `127.0.0.1:7860` — **Caddy terminates TLS** via `pipecat.r.red.mba`, so pipecat needs no cert files at all), its watchdog (probing `http://`, not `https://`), and the healthcheck script.
- Registry (`redmba` on water): add service `pipecat` on host `r` → `127.0.0.1:7860`, `check_path: /health`; **`git commit` is the deploy** (the watcher applies it). The `livekit` route already exists.
- AppVault (writes via inferno, which holds a working admin token): point `LIVEKIT_URL` + `SIMLI_LIVEKIT_URL` → `wss://livekit.r.red.mba`, and set the key pair to livekit-os's own pair (read from razer's stack env, stored in the vault — never printed). Nothing on livekit-os itself changes.
- Use `appvault run --name …` (not `--all`) on razer: `--all` reads all ~575 secrets per start and has already tripped the vault's rate limiter once.

### Phase 2 — water becomes the web host

### Risks I'll be watching

- **razer is a wifi laptop** — a materially weaker host for an SFU than a racked node; lid/suspend and radio make it the most likely cause of a dropped call.
- **Media candidates**: razer's LiveKit advertises its own interfaces (`use_external_ip: false`), so calls must be verified from your actual phone/laptop on the LAN — not just from the tailnet.
- **AppVault on razer** must hold a token bound to razer's Tailscale node ID (`nbwUJ4tuKT11CNTRL`) — tokens are host-bound, so a neon/water token won't work there.
- **Registry commit = deploy**: routes land for every host on commit, so I'll add each route only once its service is up and verified (the registry supports `pending`), not up front.
- **`livekit-os` is shared**: hotline's media now shares one SFU with nexus/jarvis/voice-agent. Nothing changes in their config, but a hotline-side misbehaviour is no longer isolated — the alternative is a dedicated instance, which is a small edit to the plan.
- Every host-touching step here is additive and reversible on existing state; nothing gets deleted, and neon keeps its data and units until you've confirmed a call works.
